# 城市区域地址库文件导入

后台位置：区域 → 城市区域地址库 → “导入地址库（文件）”。下载CSV模板，填写后选择文件、预览校验，再确认导入。

## 支持的文件

- CSV：UTF-8编码，可带BOM；第一行为表头。
- Excel：仅`.xlsx`，读取名为“导入地址”的工作表，忽略“小区信息”“车位留存”等其他表。不得包含公式。
- JSON：顶层地址数组，或对象的`import_address`数组；支持本次DEEPSEEK整理格式及每行`source_raw`来源记录。
- 每次1至5000行，文件最大15MB。不支持旧版`.xls`。

## 表头顺序

城市、区县、立即修小区编号、小区名称、贝壳小区ID、小区别名、商圈、楼栋名称、贝壳楼栋ID、原始单元名称、入口类型、单元名称、道路门牌原文、道路门牌标准写法、贝壳单元ID、房号、贝壳房屋ID、房屋类型、标准完整地址、同址别名、内部备注、来源名称、来源链接、采集时间、核验状态。

所有编号、来源ID和房号请用文本保存，保留前导零，不用科学计数法。不能使用真实客户信息填写模板样例。

## 字段与归属

- 城市、区县须先在“城市区域列表”建立，名称能唯一匹配。不会自动创建行政区。
- 立即修小区编号是公开业务编号，保留数据库内部ID；贝壳数据使用贝壳小区ID作为该编号。人工数据填写自己的稳定小区编号，贝壳来源ID留空。
- 城市、区县、小区编号、小区名称、楼栋名称、房号必填。贝壳数据须保留小区、楼栋、单元、房屋全部来源ID。
- 入口类型：普通单元、道路门牌、待确认。普通单元填单元名称；道路门牌填写道路门牌标准写法，原始值单独保留。
- 仅支持住宅、商业。车位另表留存，不混入导入地址。
- 导入总库不等于开通下单。必须另外分配给启用且开通的门店。

## 重复、冲突和待确认

- 文件预览不写入；确认时重新校验文件散列和当前数据库，整批成功或整批回滚。
- 来源房屋ID与完整地理层级匹配的已有记录跳过，不覆盖人工备注、别名、启用状态或历史订单。
- 同一来源ID对应不同地址、同一完整地址对应不同来源ID、文件内重复等冲突会阻止整批导入。
- 同楼栋不同入口允许相同房号，不合并。多入口的房屋式别名会补齐入口；原始简称保留为搜索词，不用于直接唯一选址。
- “待确认”记录可进入总库，但不向客户开放。管理员核对真实地址、修改入口类型并明确允许开放后，仍需有效门店范围才可下单。
- 来源原文、层级ID、采集时间、文件散列和操作人审计保留；内部备注不公开。

## 门店与各端选择

门店后“分配门店服务地址范围”按小区→住宅/商业/车位→整栋（道路门牌栋）展开，界面不再逐户勾选。普通单元楼合并为整栋，道路门牌分别成栋。父子复选联动；新分配草稿默认住宅和商业，车位另选，已保存范围按实际回显。旧部分门牌范围未修改时保留。类别/整栋包含后续新增的同类下级地址，不同门店不得有重叠范围。

客户报修、代客下单、地址簿、家政预约及网页相关表单使用同一总库。先选择城市/区县，输入小区名或别名并选中候选，再选楼栋、入口、房号。服务端根据房屋编号重新检查当前门店，保存标准完整地址快照。

小程序新界面需要相应开发/体验版本；正式端需审核发布后生效。

总库以同样的小区、类别、楼栋结构浏览，展开后查看门牌、单元和状态，可在对应节点新增及在门牌层修改、停用。已停用地址默认隐藏，可勾选显示。
