# 2026-11-01 统一地址源、门店服务地址范围及小程序入口修复

## 最终行为

- 城市区域列表只管理城市与下属区县；城市区域地址库为唯一地址创建、修改、停用、恢复、导入入口。地址可在门店建立前录入。
- 地址保持原 store_addresses 实体及编号，新增地址不要求 store_id；同址别名、标准门牌、内部备注、来源信息集中维护。重复地址拒绝创建，批量粘贴导入按 Tab 分列，每批最多 2000 行，任一行失败整批回滚。
- 门店服务地址范围只引用总库，按城市、区县、门店名称查询。支持整小区、整栋楼、单个地址；整小区/整栋涵盖后续新增地址。跨店重叠分配被拒绝，同区县可有多家门店。范围保存前取得区县写锁，避免并发跨店覆盖。
- 客户报修、代客下单、客户地址簿、家政需求、网页套餐购买均从有效覆盖地址选择；后端以地址编号重新解析当前开通门店，忽略伪造的文字与门店归属。历史订单和合同地址快照不改写。
- 旧门店地址写入与旧社区批量分配 API 返回明确迁移提示；官方社区基础资料保留，但不直接成为新下单范围。
- 小程序共用“我的”页恢复推荐码、复制、二维码、分享及选填绑定入口。App 捕获分享参数或扫码 scene；未登录暂存，登录后绑定，失败保留以便重试。原推荐关系和收益规则未调整。
- 检查提交订单入口：客户报修页原有表单内与底部两处；代客下单页原有底部一处，现增加表单内入口，合计两个页面四处。底部按钮提高到导航上方并留出安全区；两页面保持提交中防重复保护。家政“提交需求”也统一地址选择并补充防重复保护。
- 小程序支持楼栋/单元/房号、别名和完整门牌选择；未拆分的旧门牌可直接逐条选择，避免空房号被错误匹配为第一条。
