# 2026-11-02 总库与门店范围树形管理

## 使用方式

- 城市区域地址库默认只显示小区，展开后依次显示住宅、商业、车位，以及楼栋/道路门牌。普通单元楼按整栋归组，门牌表中显示单元和房号；道路门牌楼按“楼栋 / 道路门牌”独立归组，避免S6两个101室混淆。
- 门牌按需加载，每组50条分页；搜索小区只定位小区，搜索楼栋/入口展开相应路径，搜索房号再显示匹配门牌。已停用地址默认隐藏，可勾选显示；不删除历史数据。
- 小区、类别、楼栋节点可直接添加地址，并预填对应区域、小区、类别和入口。门牌层提供修改、删除（停用）及修改后启用，保存后保持展开位置。类别字段也可明确修改，避免编辑商业记录时意外转为住宅。
- 分配门店服务地址范围默认只显示小区，展开住宅/商业/车位后，最细复选项为整栋（或道路门牌栋），不再逐户勾选。父节点联动，部分选择显示半选，可搜索定位。
- 未分配小区的草稿默认住宅、商业勾选，车位不勾选；已保存状态优先回显。默认值只在用户点击保存后生效。没有此类地址时显示空类别并禁用其复选框。
- 其他门店已覆盖的整栋/入口不重复勾选。既有部分门牌范围不自动扩大或删除；未修改时原样保留，明确勾选整栋才改为整栋范围。已停用地址的旧范围也保留。
- 待确认商业可在目录及范围中看到，但即使分配仍不可下单，地址核验与门店分配独立。

## 服务端

- address_coverage新增可空property_type，空值兼容原有范围。新范围可按住宅、商业、车位分别保存；住宅类别覆盖后续新增住宅，但不会带入商业或车位。
- 冲突校验同时检查类别、楼栋和入口；不同类别可由不同门店服务，重叠范围拒绝保存。各端订单继续通过同一resolve_address/public_catalog校验有效门店，不更换房屋编号或历史快照。
- 修复新增/修改地址响应的updated_at异步懒加载问题：提交后刷新模型，再返回，避免数据已保存却接口500。
- 手动新增车位按车位编号生成，不默认追加“室”。本次未导入任何车位。

## 回滚

新增类别字段兼容旧记录，但用户保存类别范围后不能直接切回忽略类别的旧代码，否则可能扩大服务范围。回滚前应先核对新增分配与业务数据，协调恢复代码和数据，不盲目覆盖上线后操作。
