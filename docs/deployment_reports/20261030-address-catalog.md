# 2026-10-30 层级地址库与同址别名

## 数据结构和操作

- 延用 store_addresses.id 作为实体地址 ID；层级字段为服务区域、小区/分期 estate、楼栋 building、单元 unit、房号 room。无单元可留空。
- door_number 保存标准门牌写法，未填写时由结构字段组成；aliases 保存同一实体地址的其他写法，一行一个，也可用中文分号分隔。
- 示例：小区“蓝月湾一期”、楼栋“S5栋”、房号“2605”，标准写法“嵩屿北五里27号2605室”，别名“厦门市海沧区蓝月湾一期S5栋2605室”。这是一条实体记录，不是两条地址。
- detail_hint 为内部备注；source_name、source_ref 记录来源名称及小区编号/链接。支持把贝壳页面中的各级选项分别复制到对应字段，本次未自动采集贝壳数据，也未实现整表批量导入。
- 后台“门店 → 门店地址库”支持新增、修改、删除；删除为 enabled=false，不删除实体记录或历史订单。后台后续如需恢复，可由管理员通过 PATCH enabled=true 恢复。
- 地址创建/修改由服务区域确定有效门店；店长只能维护自己负责门店，删除仅平台管理员可操作。
- 管理员维护的地址发布到客户端下拉，客户个人保存的地址不自动公开。内部备注、创建者和业务负责人不在游客目录返回。

## 客户端同步

- 小程序客户下单、代客下单、个人地址簿共用地址组件：城市/区域 → 小区 → 楼栋 → 单元 → 房号；支持同址别名选择及门牌手填兼容。
- H5 使用同一词汇，支持标准地址/别名搜索和楼栋单元房号候选联动。
- 选择实体地址后传 address_book_id（个人地址簿用 service_address_id）；后端读取实体地址和当前门店，忽略伪造的小区门牌；历史订单快照不跟随地址编辑改变。
- 旧地址 117 条保留，不根据字符串猜测拆分、合并或判断同址。管理员可逐条补全结构和别名；保存后进入层级选择。新增 catalog_published 标记防止既有私人地址自动公开。
